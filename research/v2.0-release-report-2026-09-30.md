# Garhwali Language Lab V2.0 corpus update — 2026-09-30

## Result

The post-ingestion local pipeline completed. It rebuilt canonical text, quality
tiers, language resources, split manifests, benchmark and instruction views,
both Hugging Face profiles, the metadata reference index, README metrics, and the
project file map. The update adds **164 net-new exact-unique text values** from
the pinned Garhwali Language Library static files. It does not remove any
previously collected source layer. Jambu and the small Hikinegi Hub dataset were
rechecked and add no new unique Garhwali output strings.

The package and segment figures include overlapping configurations and views;
they are not independent-text sample counts. The 2.94M whitespace-token value
is not linguistic tokenization. Automated quality tiers are screening evidence,
not native-speaker validation. Native review and dialect annotation remain
deferred.

## Further public-source search

The follow-up searched Hugging Face, lexical databases, Indian language-data
catalogues, university repositories, and public dictionary pages. The most
promising additional material is real but not yet an authorized text payload:

| Lead | What the public source confirms | Next step before ingestion |
| --- | --- | --- |
| [LDC-IL Garhwali Parallel Text Corpus](https://www.ldcil.org/releaseddataset) | The official released-dataset catalogue lists a Garhwali parallel corpus. | Obtain the language component, sample, price, and model-training/redistribution terms from LDC-IL; then exact/fuzzy-deduplicate the authorized export. |
| [LDC-IL Are Parallel Text Corpus](https://data.ldcil.org/are-parallel-text-corpus-linguistic-features-and-structures) | The product page describes 5,332 sentence/phrase pairs per language across 146 mother tongues, but it does not establish that Garhwali is included in this particular product. | Confirm coverage, component cost, and terms. |
| [Uniyal, 2019 English–Garhwali SMT paper](https://www.pramanaresearch.org/gallery/prj-p431.pdf) and [HNBGU CV](https://www.hnbgu.ac.in/sites/default/files/2023-09/Arushi_Uniyal_CV_2023.pdf) | The paper describes 40,000 monolingual and 30,000 parallel examples; the CV describes 70,000 digitized sentences. The public pages do not expose those data files or a reuse license. | Seek the exact source files, provenance, and written reuse terms from the author/university; measure overlap with the existing magazines, web pages, and scripture before integration. No outreach was sent. |
| [TUFS repository record for Pushkar Singh Kandari's 392-page idiom/proverb book](https://tufs.repo.nii.ac.jp/records/17829) | The catalogue provides bibliographic metadata and cover/title/contents files, not the full book text; it lists Vani Prakashan (2003). | Request an authorized full copy and explicit digitization, training, and redistribution terms. |
| [Hindwi Garhwali dictionary](https://www.hindwidictionary.com/garhwali) | A live dictionary page describes a Garhwali lexical collection and meanings; no open dataset export or reuse license is stated there. | Ask the rights holder for a machine-readable export and license; do not scrape its protected entries into a public dataset. |
| [Garhwali UKC Lexicon](https://datascientiafoundation.github.io/LiveLanguage/datasets/gbm-ukc-lexicon-/) | Its catalogue advertises a tiny one-word/synset resource under CC BY-NC-SA, with Wiktionary/WordNet provenance. | It is not open for unrestricted public dataset/model release and appears too small to add useful breadth; do not import without a use-specific decision. |

The ASJP wordlist and Hikinegi dataset were not missed: both are already in the
local corpus and exact overlap checks found zero additional unique forms. The
new institutional leads are acquisition tasks, not data rows. Public access,
search indexing, or a catalogue entry does not by itself grant text-reuse
rights. The full source inventory is in
[`sources/online/deep-search-catalog.md`](../sources/online/deep-search-catalog.md).

## Quality and release checks

- The full refresh is reproducible with
  `PYTHONPATH=scripts .venv/bin/python scripts/refresh_corpus_after_ingestion.py`.
  The command performs pinned-source validation and rebuilds downstream local
  views in order; it does not recrawl the web or upload to Hugging Face.
- The public Hugging Face profile includes only rows that pass the current
  row-level redistribution filter. It redacts **26,330** catalog text values
  and withholds full content for **216** structured records with unresolved
  public reuse terms. These values are retained in the local all-data view and
  represented in the metadata-only reference index; they are not deleted.
- The V2 public package has no audio payload. The existing public speech dataset
  remains a separate companion and was not rebuilt or replaced by this text
  refresh.
- The additive V2.0 package contains **36 versioned files / 561,166,047 bytes**.
  The complete payload was uploaded under `releases/v2.0.0/` at [commit
  `5db2673`](https://huggingface.co/datasets/rushilrawat/garhwali-corpus/commit/5db26737c4dcb4bd3e6a3750d30c2d9cae3048c1). The
  corrected root and release cards were uploaded at [commit
  `53a0aff`](https://huggingface.co/datasets/rushilrawat/garhwali-corpus/commit/53a0aff5ebaf7e676954065d86e2d78c0ff70504). A fresh Hub metadata check
  confirms the repository is public, the latest revision is `53a0aff`, and the
  V2.0 manifests and versioned files are present. The Hub currently exposes 15
  Parquet conversions across the V2.0 configs and splits. The upload used no
  delete patterns; the prior v0.2.0 files remain in the repository.
- The V2.0 corpus package contains no audio. The separate public speech dataset
  was not changed by this text/corpus release.
- No paid Hugging Face job or compute credit was used for ingestion or corpus
  rebuilding.

The refresh and report are documented in
[`corpus-preparation-status.md`](corpus-preparation-status.md),
[`finalreport.md`](../finalreport.md), and the generated
[`project file map`](../PROJECT_FILE_MAP.md). The local working-tree test run
passes **656/656 unittest checks**. This update improves reproducibility and
adds 164 exact-new strings; it does not produce new model scores, clear the
benchmark for public release, or establish native-validated accuracy. GitHub
publication of the accompanying code and documentation is the remaining action
for this V2.0 update.
