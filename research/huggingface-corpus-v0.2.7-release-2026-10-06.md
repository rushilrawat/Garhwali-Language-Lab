# Hugging Face corpus v0.2.7 release

Published on 6 October 2026 at [commit `1f7b2ce`](https://huggingface.co/datasets/rushilrawat/garhwali-corpus/commit/1f7b2ceed1b743412b75d6288757e1d2cadac9c4).

## What changed

The additive release introduces a dedicated `paharili_gbm` configuration with **14,988 normalized-unique text rows** derived from 15,000 upstream rows labeled Garhwali (`gbm`). Those rows contain 236,566 whitespace-separated words and 1,091,695 characters. The content is intended for text-language-identification research, not as a native-reviewed general language-model corpus or an independent evaluation set.

The 15,000 source rows contain 14,989 distinct normalized texts after collapsing 11 repeated source rows. One of those texts already existed in the public `text_expansion` view, so it remains there rather than being duplicated in `paharili_gbm`. The new config contains 14,999 source record IDs; the remaining source ID is preserved on that existing matching record. All source IDs and original surface variants remain traceable.

| PahariLI split | Rows | Meaning |
| --- | ---: | --- |
| `train` | 11,989 | Upstream training rows with normalized-unique text |
| `test` | 2,995 | Upstream test rows with normalized-unique text; not an independent project evaluation set |
| `source_overlap` | 4 | Text groups occurring in both upstream train and test; isolated from both |

The upstream repository declares Apache-2.0. Its README does not identify sentence-level source origins, so the release preserves that declaration while marking the underlying content rights and Garhwali labels unresolved/unreviewed. Rows are openly accessible in the separate config; the package does not represent them as rights-cleared or native-validated. `recommended_for_general_language_model_training` and `training_eligible` are false. The upstream training split is marked experimental only.

## Corpus totals and storage

The v0.2.6 public profile contained 168,388 content/config view rows. v0.2.7 contains **183,376**, a net addition of **14,988** rows (+8.9%). These are config views and can overlap; this is not a unique-row total. The unchanged 18,598-row `text` config remains separate from the PahariLI text-classification data.

The release also includes the updated complete reference tables: 355,846 `record_index` rows, 9,571 deduplicated `source_catalog` rows, and 412,740 `record_sources` joins. Counting these metadata views gives 961,533 total view rows; reference rows are not training examples. Across all retained versions, Hugging Face reports repository storage increasing from 5,919,695,363 bytes (5.513 GiB) to 6,415,712,470 bytes (5.975 GiB), a 496,017,107-byte increase. The v0.2.7 upload plan contained 58 files and 949,712,302 bytes; unchanged objects were reused by content hash.

The public `catalog` still has 36,105 rows: 12,657 with text and 23,448 with blank text fields in that config. The subsequent cross-config availability audit found 15,004 of those values elsewhere in the public package and 8,444 distinct full texts not present in any public config. See the [availability audit](huggingface-corpus-gap-resolution-2026-10-06.md). This wording update does not change the v0.2.7 payload or rights decisions.

## Validation

- Public-package preflight passed with 29 config/split views, no validation errors, and no deletions or mutations.
- The project virtual environment passed all **816 tests**. The system Python lacked `langgraph`; the supported project environment (`.venv`) supplied the declared pipeline dependency.
- A streaming `load_dataset` call at the exact commit read three rows from `paharili_gbm/train`; the returned rows had `iso_639_3=gbm` and retained their unresolved rights/unreviewed quality labels.
- A live repository check confirmed the v0.2.7 prefix, its PahariLI files and manifest, the public visibility, and preservation of the v0.2.6 release.
- Dataset Viewer processing completed. The live `/is-valid` response enables preview, viewer, search, filter, and statistics. `/splits` returns all 29 config/split entries and `/parquet` returns 29 exports, with no pending or failed configs. A live `/rows` request returns three examples from `paharili_gbm/train`, preserving `gbm`, the upstream split, and the unresolved rights label. Hugging Face describes these viewer conversions as queued preprocessing jobs in its [Viewer server guide](https://huggingface.co/docs/dataset-viewer/en/server).

## Rebuild

The source transformation is implemented in `scripts/build_huggingface_dataset.py`; the reference tables and public-availability links are generated by `scripts/build_hf_reference_index.py`. Rebuild the public package, reference tables, preflight it, then run `scripts/prepare_hf_additive_upload.py` to stage an additive versioned upload. Raw PahariLI snapshots remain ignored local inputs; the release preserves their source URLs, hashes, row indices and upstream license text.
